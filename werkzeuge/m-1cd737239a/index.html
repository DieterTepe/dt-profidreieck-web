Bereit.

Auf einen Blick

Hier steht das Wichtigste aus allen Quellen. Klicks bei Google und Bing sind die besten Hinweise auf echte Besucher. Die GitHub-Zahlen zeigen nur, wer sich deinen Code auf github.com ansieht – nicht, wer deine Webseiten besucht.

Automatiken auf GitHub

Zeigt, ob die automatischen Helfer zuletzt geklappt haben: Veröffentlichung (Seite ist online), Linkprüfung (keine kaputten Links/Bilder), IndexNow (Bing wurde benachrichtigt), Lighthouse (Wochen-Messung). Grün = gut, Rot = antippen und nachsehen.
Noch nicht abgefragt – oben „Abrufen“ tippen (Token nötig).

Was sollte ich tun?

Google & Bing

Impressionen = wie oft eine deiner Seiten in den Suchergebnissen angezeigt wurde. Klicks = wie oft jemand darauf getippt hat – das sind echte Besucher. Position = durchschnittlicher Platz in der Trefferliste (1 = ganz oben; kleiner ist besser). CTR = Klicks geteilt durch Impressionen.

Nach Sprache & Programm

Aus der Seiten-Liste des Exports erkannt: Adressen mit /en/ = Englisch, /pt/ = Portugiesisch, sonst Deutsch. So siehst du, ob die neuen Sprachseiten gefunden werden.

Daten hineinladen

So exportierst du aus der Google Search Console
  1. search.google.com/search-console öffnen, oben links die richtige Property wählen.
  2. Links Leistung → Suchergebnisse. Oben den Zeitraum wählen (z. B. „3 Monate“).
  3. Oben rechts Exportieren → CSV herunterladen. Es entsteht eine ZIP-Datei im Download-Ordner.
  4. Hier „Quelle: Google“ und dieselbe Webseite wählen, dann die ZIP-Datei auswählen. Fertig.

Tipp: Am besten einmal pro Woche oder Monat. Neue Exporte werden mit den alten zusammengeführt – so entsteht eine lange Historie (Google selbst zeigt nur 16 Monate).

So exportierst du aus den Bing Webmaster Tools
  1. bing.com/webmasters öffnen, oben die Webseite wählen.
  2. Links Suchleistung. Zeitraum wählen.
  3. Die Diagramm-Daten bzw. die Tabellen „Suchanfragen“/„Seiten“ über Herunterladen (Pfeil-Symbol) als CSV speichern.
  4. Hier „Quelle: Bing“ und die Webseite wählen, dann die CSV-Datei(en) auswählen.

Code-Aufrufe auf github.com

Wichtig: Diese Zahlen zählen, wer sich deine Repos auf github.com ansieht (Dateien, Code, README) – oft du selbst, Claude oder Bots. Besucher deiner Webseiten (dt-profidreieck.de, Testversionen) sind hier nicht enthalten; GitHub liefert dafür keine Zahlen. Echte Besucher-Hinweise findest du unter „Suche“.
Was heißen „Aufrufe“, „Besucher“, „Klone“?

Aufrufe (Views): jedes Laden einer Seite des Repos auf github.com – auch Neuladen und Bots.

Besucher (Uniques): verschiedene IP-Adressen pro Tag. Eine Person an 7 Tagen = 7 Besucher.

Klone (Clones): wie oft das Repo komplett heruntergeladen wurde – meist durch Claude, GitHub selbst oder Werkzeuge.

Herkunft: von welcher Seite Leute zu deinem Repo kamen (z. B. google.com, github.com).

GitHub liefert nur die letzten 14 Tage. Der Monitor speichert jeden Abruf, so entsteht eine längere Historie – also ab und zu abrufen.

Herkunft & meistgesehene Dateien (14 T)

Lighthouse – Ladezeit & Qualität

Google misst jede Woche (montags) deine Seiten in der Handy-Ansicht. 0–100 Punkte je Bereich: Leistung (wie schnell), Barrierefreiheit (gut bedienbar), Best Practices (technisch sauber), SEO (für Suchmaschinen lesbar). Ab 90 grün, 50–89 gelb, darunter rot. Leistung schwankt von Messung zu Messung um einige Punkte – auf den Trend achten.

Woher bekomme ich die ZIP-Datei?
  1. Oben „↗ Berichte auf GitHub“ antippen (angemeldet sein, im Browser – nicht in der GitHub-App).
  2. Den obersten (neuesten) Lauf öffnen, ganz nach unten zu Artifacts scrollen.
  3. lighthouse-berichte antippen → ZIP wird geladen. Hier auswählen.

GitHub-Token

Ein Token ist wie ein Schlüssel, mit dem der Monitor deine GitHub-Zahlen abfragen darf. Er bleibt nur auf diesem Gerät und wird nirgendwohin gesendet außer an GitHub.
Sicheren Token anlegen (empfohlen)
  1. github.com → Profilbild → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  2. Name z. B. „Monitor“, Ablauf z. B. 1 Jahr.
  3. Repository access: „Only select repositories“ → die 5 Repos wählen.
  4. Permissions → Repository: Administration: Read-only (für die Aufrufzahlen) und Actions: Read-only (für den Status der Automatiken). Alles andere aus lassen.
  5. Erzeugen, kopieren, hier einfügen, „Token prüfen“.

Ein alter „Classic“-Token mit repo-Recht funktioniert auch, darf aber viel mehr (auch ändern und löschen). Wenn du den neuen nutzt, den alten bei GitHub löschen.

Automatisch abrufen

Beim Öffnen wird automatisch abgerufen, wenn der letzte Abruf älter als 6 Stunden ist.

Datensicherung

Alle Daten liegen nur im Browser dieses Geräts. Leert man den Browser-Speicher, sind sie weg. Deshalb ab und zu „Sichern“ – die Datei landet im Download-Ordner. Auf einem anderen Gerät mit „Einlesen“ übernehmen; doppelte Tage werden automatisch zusammengeführt.

„Einlesen“ versteht auch Sicherungen aus dem alten Monitor (dt_profi_historie.json).

Speicher & Neuanfang

Der Monitor räumt beim Öffnen und nach jedem Abruf selbst auf: Von den GitHub-Zwischenständen bleibt nur der letzte je Tag, von „Herkunft & Dateien“ höchstens 60 Tage. Tageswerte, Suchdaten und Lighthouse bleiben vollständig. Doppelte Importe überschreiben sich selbst – es entstehen keine Doppelzählungen.
Daten zurücksetzen (neu anfangen)

Meist nicht nötig. Sinnvoll z. B., wenn versehentlich Daten der falschen Webseite eingelesen wurden. Google- und Bing-Daten kannst du jederzeit neu exportieren (Google: 16 Monate, Bing: 6 Monate zurück) – GitHub-Zahlen dagegen nur 14 Tage.

Als App auf dem Startbildschirm

In Chrome oben rechts ⋮ → „App installieren“ bzw. „Zum Startbildschirm hinzufügen“. Danach öffnet sich der Monitor wie eine eigene App.

Wörterbuch

Impression · Klick · CTR · Position

Impression: deine Seite wurde in der Trefferliste angezeigt (auch wenn niemand hinsah). Klick: jemand hat sie angetippt. CTR: Klicks ÷ Impressionen; 2–5 % sind für Fachseiten normal. Position: durchschnittlicher Platz; Seite 1 = Position 1–10.

Indexierung · Sitemap · hreflang

Indexierung: Google nimmt die Seite in seinen Katalog auf – erst dann kann sie gefunden werden. Sitemap: Inhaltsverzeichnis für Suchmaschinen. hreflang: sagt Google, welche Seite für welche Sprache ist.

Lighthouse-Werte (LCP, CLS, TBT)

LCP: Zeit, bis das Hauptelement sichtbar ist (gut < 2,5 s). CLS: wie stark die Seite beim Laden springt (gut < 0,1). TBT: wie lange die Seite „hängt“, bevor man tippen kann (gut < 200 ms).

Warum sind die GitHub-Zahlen keine Besucher?

GitHub zählt nur Aufrufe der Repo-Seiten auf github.com. Deine Webseiten werden über GitHub Pages ausgeliefert, und dafür gibt GitHub keine Zahlen heraus. Ein Besucherzähler auf der Seite wäre möglich, widerspricht aber dem Grundsatz „keine fremden Skripte“. Daher: Suchmaschinen-Klicks als Maßstab.
